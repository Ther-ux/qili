# 稳定性优化与回归检查

日期：2026-10-22。范围为本地程序，不发布博客、不推送 GitHub、不公开部署。

## 修复的问题

| 问题 | 修复方式 | 检查结果 |
| --- | --- | --- |
| 两个页面先后保存完整旧快照，导致另一页完成记录被覆盖 | IndexedDB 单题读写事务，读取最新记录后在同一事务内更新；通过 BroadcastChannel、存储通知和页面重新聚焦同步显示 | 两页交替完成不同题目，均同步到 4/20；刷新后两项完成标记都保留 |
| 提示或讲解请求失败，也提前把本轮标记为已辅助 | 仅在提示或讲解内容成功显示后标记辅助；失败请求不修改该标记 | 提示失败、教案和 AI 请求失败后再解题，均正确显示独立完成；成功看提示后解题仍显示提示后完成 |
| 可选引擎启动或分析失败时，连带阻止模型讲解 | 先校验题目和历史，再尝试引擎；引擎失败后提供规则证据，并明确显示未使用引擎 | 模拟引擎异常时讲解继续；两组对照均使用相同规则证据和空引擎结果，均有降级说明 |

实际模型服务失败仍然显示失败，不把规则降级当作模型成功；错误题目历史仍返回 400，不发送给引擎或模型。模型提示明确禁止在没有引擎证据时声称提供引擎评分。

## 学习记录兼容与边界

- 首次打开新版时，将 `qili-study-v1` 的允许字段迁移至本浏览器的 `qili-learning-v2` 数据库；迁移在事务内执行且只进行一次。
- 原 localStorage 记录不删除、不改写，保留作迁移前副本。它不再反映新版后续进度；需要备份当前进度时使用页面“导出记录”。
- 继续兼容原 `app: qili-study, version: 1` 的 JSON。导入只替换文件中明确列出的题目，其余题目不变；导入前仍要求确认。
- 数据库只保存题号、作答次数、失误次数、完成/独立完成/错题解决状态和时间，不保存 API Key、访问口令或模型回复。
- 写入事务失败时不假装已经保存，页面给出提示并保留本页进度；若写入已提交、仅页面刷新记录失败，则明确提示“进度已保存，但页面同步失败”。
- 同步限于相同浏览器、相同来源；不同端口、浏览器、设备之间不会自动同步。浏览器清理网站数据仍可能清除进度，建议定期导出。
- 更新后需刷新旧页面才能启用新存储逻辑。刷新会按既定设计清除本页 API Key，需要重新输入。
