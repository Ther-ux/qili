## v0.2.5 反例说明与一次完整检查

真实诊断新增 S10 原因引用 `e7f7`。按同一局面重放，主着 `e8e7` 后，f7 为己方黑士，黑将不能走 `e7f7`。旧校验无法区分“说明为什么不能走”与“推荐实际执行”；由于没有原始 DS 句子，本记录不推定它究竟采用哪种说法。

每步走前／走后事实现列出双方帅将邻格的试走坐标 attempt、合法性 legal、己方占位 blockedBy、出九宫 outsidePalace 及试走后攻击者。legal:false 不进入合法着法列表；只能在正文明确写成不能执行的反例。无工具依据的坐标及把这些反例写成正面推荐仍被拒绝；不会把“不能走”示例加入可回放主线。提示词提供明确写法并要求说明具体原因。自然语言检查不等于完整棋理或语义证明。

校验现在一次检查所有步骤和字段，按步骤与分支编号汇总补写目标，传入具体失败项；有多个问题时一次补写覆盖全部已发现部分。修复补写总览字段时的分支归属错误，避免总结未被加入补写目标。原本正确的应对与其他段落保留；仍然每次用户请求最多一次模型调用。145 项 Windows 自动测试全部通过、无跳过，20 题可解性检查通过，包含 S10 原位、己方占位、出宫反例、正面推荐与无依据反例拒绝，以及多字段一次发现并修复。模型生成使用模拟接口，尚未取得修复后真实 DS 完整回复。

## v0.2.4 实际失败修复

本机诊断记录了两次真实失败：S2 对方应对要求 3 项却返回 0 项；另一次在 S2 原因中引用 `h0g0` 被坐标白名单拒绝。以用户这盘原局面重放 `g0i2` 后，黑方完整合法走法是 `d7e8 e7e8 f7e8 g5i7 h0g0 h0i0`，所以后一项属于程序误拦。

每步现提供走前 `legalMoves` 和主着走后 `replyLegalMoves` 全部合法着法。讲解可以引用未进入三条引擎样本的合法候选，但列表只证明合法性，没有独立分值和后续的候选不能被写成败着或胜着。非法坐标仍拒绝；多步变化仍以经过重放的工具线路为准。补充 `requiredCoverage` 清单，明确列出每步、其他走法、对方应对的全部编号，减少长回复漏项。工具明确没有分支时，允许省略空数组。

三个入口共用 `src/coach-completion.js`。失败的结构化草稿最多保留 8 份、10 分钟，仅进程内存；缓存用进程随机盐的 HMAC 隔离页面 Key、模型和任务，缓存不保存 Key、提供商完整响应或思考内容。失败时告知草稿已暂存，用户再次点击才发起一次补写调用；不会自动追加计费请求。补写只允许覆盖指定字段或编号，原有内容及原始核验证据保留；完整合并后重新检查所有步骤、坐标、证据和胜负结论，失败仍不显示成 DS 完整讲解。更换局面、模型或 Key 不会复用其他任务草稿，成功或超时后清除。

2026-10-22 Windows 自动测试 141 项全部通过，无跳过；20 题可解性检查通过。新增实盘合法候选回归、保留原文与证据、错误补写不覆盖草稿、非法坐标继续拒绝、跨 Key／模型／任务隔离与过期，以及三个 HTTP 入口一次请求一次调用的补写流程。模型生成仍使用模拟接口；实际 DS 的再次完整输出尚未验收。

## 教学要求

每步说明具体问题、为什么现在走、成立条件、走后变化、对方不同应对与我方后续。点名棋子、起终点与关键格；不能用规则合法、注意安全或加强配合代替原因。第一次使用炮架、马腿、象眼等术语时，结合本局面解释。

程序从真实走前／走后 FEN 计算双方子力、当前行棋方的合法吃子机会、帅将合法移动及移动路径条件；吃子机会不等于安全得子，不把可吃直接说成白吃。每步最多 3 条其他走法及 3 条对方应对，分别展示并可回放。应对线路来自规则复盘或有范围限制的搜索；纯合法示例明确标注，不伪称最佳应对。

JSON 契约要求双方每一步、每条变化和每条应对均有讲解。原因至少 60 字且引用实际坐标或记谱，应对与变化各至少 40 字，总结至少 80 字；编号、坐标、步骤遗漏与截断会拒绝。长度和锚点不能代替完整语义事实审核。

逐步讲解、应对说明、变化解释和教学总结仅展示通过校验的 DS 输出。本地模板保留在后台作为 DS 上下文，页面只保留参考着法与简短核验信息；初次求解、等待 DS、调用失败时，详细讲解区为空。普通题、预置残局和导入局面一致；无需先生成 DS 讲解也能从参考着法开始摆谱，退出摆谱不会显示本地模板。按真人棋评资料提炼分析顺序，附两段本项目自编写法示范，出处见 [研究记录](COACH-RESEARCH.md)。引擎按同一根局面的候选进行 MultiPV 比较，仅采纳同一完整深度的结果；cp 分值可作有限搜索对比，mate 与区间界限不直接相减。保留已有正确解的证明线路，避免被不同参考线路覆盖。主着与候选分别给实际变化末尾、吃子记录和子力构成，供 DS 解释具体效果。对照评测的两组复用相同比较证据。

## 胜负

总结以“胜负结论：红胜／黑胜／胜负暂未确定”开头，结论由程序提供，DS 无权改写。

当前已经绝杀／困毙，或覆盖全部合法防守的短将杀证明，支持明确胜者。参考线路某个分支末尾取胜，只能说明该分支；有限引擎搜索的正分、mate 分值、零分及搜索无解，均不能代替完整胜和负证明。当前未实现完整残局库、循环和长将长捉裁定，因此不能在缺少依据时输出和棋；引擎零分写作暂评接近平衡。

## 摆谱阅读和调用

进入摆谱后隐藏原步骤讲解、导航、变化和总结，居中突出棋盘和操作。走棋不调用模型。点击“AI 分析当前局面”才分析当前真实位置，在棋盘下方全宽显示结论、胜负与建议，展开后看每步原因及对方应对。分析期间仍可走棋；迟到结果丢弃，继续走棋后需重新点击。支持悔棋、重摆、从应对末尾继续研究和返回主线，不改变训练成绩。

服务器重放最多 80 步合法历史，忽略客户端伪造的 FEN 和引擎结果。每分钟最多 30 次摆谱分析。思考模式开启、effort high；最多 32000 tokens，超时 120 秒，无自动重试。连接测试和识图不启用思考。

## v0.2.3 校验误拦修复

用户同盘兵卒士象残局可复现：其他走法讲解对照主着 g0i2 时，被误判为引用当前步骤之外的着法。现在主着、其他走法及对方应对可引用当前步骤给定的工具着法，仍拒绝未提供的着法。引擎 12 步参考与可重放线路一致，末尾工具事实也可引用；各数组按唯一 ID 定位，兼容返回顺序差异，重复、遗漏或陌生 ID 仍拒绝。总结仅兼容冒号与空白差异，不改写胜负结论。

失败诊断区分 JSON 无效、空回复、输出截断、具体步骤的字段／覆盖／编号／坐标／证据错误，以及总结胜负不符。普通题、导入和摆谱统一处理，不追加自动模型重试；失败时保留局面与本地线路，不能冒充 DS 成功。

仅本机模式提供 GET `/api/coach/diagnostics`，返回模型是否忙碌，以及内存中最近最多 8 条失败的时间、接口、错误码和校验项。重启清空，不保存或返回原始模型回复、图片、FEN 或 Key；非本机服务模式返回 404。后端修复可在原页面直接手动重试，无需刷新而丢失 Key 和局面。

135 项测试通过，包含原局面对照主着、按 ID 排序、完整 12 步参考、6 类 HTTP 诊断、私密数据不回显、诊断上限和公网关闭，以及网页失败保留棋盘并允许重试。旧版吞掉了具体原因，且本轮浏览器连接没有暴露用户标签页，不能恢复旧 DS 原文或断言旧失败恰由哪一项触发；本次确认并修复的是可复现的程序误拦与诊断缺失。
