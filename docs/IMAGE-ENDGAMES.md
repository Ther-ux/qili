# 图片残局导入与求解

> v0.2 新版默认改为自动定位 → 本机裁剪校正 → 分格识别与分歧校对，见 `AUTO-VISION.md`；逐步讲解和自由摆谱见 `DETAILED-COACH.md`。以下为初版图片残局设计与阶段验收记录。

## 使用

1. 启动本地程序，打开左侧“图片残局”。
2. 选择完整清晰的棋盘图片（PNG、JPEG、WebP，原文件最多 10 MB），尽量先裁掉棋盘外的个人信息。
3. 指定原图下方为红方或黑方，并指定谁先行；图片无法可靠证明该轮应谁走，不能交给模型猜。
4. 在 API 设置输入自己的 DeepSeek Key，模型选 `deepseek-flash`。勾选图片发送授权，点击“AI 识别棋盘”。选择文件不会自动上传。
5. 对照左侧原图，检查右侧棋子。使用下方红黑棋子或“擦除”工具点击交叉点校正；下方固定为红方底线。也可粘贴 FEN，再点击“导入 FEN”。
6. 勾选局面确认，选行棋方 1–3 步范围，点击“核验并求解”。本步骤不使用模型，不需要 Key。
7. 查看结论、工具证据和逐步线路；选择某一步可查看走后棋盘，点击“返回原局面”后才可校正。
8. 如需自然语言解释，点击“AI 解释解法”，会实际调用一次所选文字模型。导出分析可保留确认后的 FEN、参考线路、证据与本次解释，不包含 Key 或图片。

没有 Key 时，可点击“先用示例残局体验”，或者手动摆棋/FEN 导入，直接测试本地求解。

## 原理与边界

- 图片转录使用固定官方 `https://api.deepseek.com/chat/completions`，禁止自定义第三方地址和外部图片网址。官方当前文档注明 `deepseek-flash` 支持图片，`deepseek-v4-pro` 不支持图片；pro 仍可用于后续文字讲解。[视觉指南](https://api-docs.deepseek.com/guides/vision/)、[模型说明](https://api-docs.deepseek.com/quick_start/pricing/)。
- 浏览器解码后重新绘制 JPEG，去除原始 EXIF 等文件元数据，最长边压缩至 1600 像素，压缩后的图不超过 1.5 MB。图片本身仍可能含有隐私文字，必须由上传者先裁掉。
- 模型返回的 10×9 字符棋盘先作为草稿展示。结构校验不代表识别准确；静态检查通过后仍须人工确认，不自动求解。
- 后端检查帅将数量、九宫、士象可达位置、兵卒位置、标准棋子数量、行棋方及将军状态。这不是对整段历史可达性或长将长捉的完整证明。
- 连续将杀搜索支持任意一方先行。进攻方每步必须将军，防守方全部合法应对均参与核验。仅成功完成该搜索时标为“已核验短连续将杀”。展示线路是其中一条最长防守线路，不等于只验证这一条。
- 搜索限于 1–3 个进攻方回合、最多 16000 节点及约 1.2 秒工作预算；独立线程总等待上限 2.2 秒。达到资源上限或没找到，只能视为尚未证明，不标为和棋。
- Pikafish 使用最多 1200 ms 搜索，推荐线路逐步通过合法性检查后才展示。有限搜索的 mate 分值可能包含困毙，不能直接当作绝杀证明。
- AI 只能解释后端重新获取的已核验证据，前端不能提交伪造的“必胜结果”。输出格式、候选着法和证据编号受检查，但自然语言战术解释仍需审阅。
- 当前不支持 XQF/CBR 文件、整盘文字棋谱及图片中多个棋盘同时识别；每次使用一个完整棋盘。

## 数据与费用

图片识别和 AI 解释分别由按钮触发，均可能产生服务商费用；本地求解不产生模型费用。页面 Key 只在当前页面内存中使用，不读取旧 `.env` 模型密钥。

图片不保存为服务器文件，不写入浏览器持久存储；会按用户授权发送到 DeepSeek。后端仅对确认后的 FEN 分析做最多 32 项、2 分钟的进程内短时缓存，不保存原图或 Key；服务商的数据政策另行适用。

自定义残局与原 20 题的学习记录隔离，不计入独立完成数。修改棋子、行棋方、方向或重新导入后清除旧解法和确认状态；修改搜索范围清除旧分析。导出不会携带原图、模型设置或密钥。
