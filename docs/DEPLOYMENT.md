# 最终上线准备（本轮未部署）

当前监听 `127.0.0.1:8787`，只供本机使用；其他人的电脑不能直接访问这个地址。GitHub 代码仓库或静态 Pages 不会自动启动 Node 后端、Pikafish 或模型接口。

## 预期部署方式

使用可运行 Node.js 22.9+ 和独立子进程的 Linux/Windows 服务器，反向代理提供 HTTPS。单实例先采用共享访问口令和有界引擎队列，用于课程验收；更大规模开放需要用户级配额与成本预算。

- Windows：可使用随附同版本引擎及权重。
- Linux：从随附对应源码按官方说明编译匹配系统架构的引擎，设置 `PIKAFISH_PATH`；不要尝试执行 Windows `.exe`。
- 权重放在项目 `engine/pikafish.nnue`，并保留其许可。引擎和权重分发要求见 `THIRD_PARTY.md`。

配置示例（值由部署者填写）：

```dotenv
HOST=0.0.0.0
PORT=8787
APP_ACCESS_TOKEN=足够长的随机专用口令
PUBLIC_ORIGIN=https://实际部署域名
PIKAFISH_PATH=/实际路径/pikafish
```

`APP_ACCESS_TOKEN` 不是模型密钥。访问者在网页设置里输入项目口令，在 API 设置里手动填写自己的模型密钥；密钥只在当前页内存保留，经 HTTPS 后端转发到 DeepSeek 官方接口，不在服务器持久保存。刷新后必须重新输入，服务器不再使用环境变量中的模型配置。反向代理后所有访客可能共享一个源 IP，本版按连接 IP 限流会合并这些访客，因此小规模验收前也应验证容量，不盲目信任客户端提供的转发 IP。

## 上线前检查

1. 自动化测试通过；对应平台的真实引擎可用；真实模型调用与异常回退均验证。
2. API 密钥、`.env` 不进入仓库或公开静态目录；关闭调试日志中的敏感数据。
3. 设置访问口令、正确 `PUBLIC_ORIGIN`、HTTPS 和反向代理超时；Node 端口不直接暴露公网。
4. 测试不同浏览器/用户不会互相覆盖棋盘状态；本版每次分析独立进程，无共享局面广播。
5. 设定模型总预算和引擎并发预算，检查限流、队列满、网络超时。
6. 提供真实访问地址、测试口令的安全发放方式、代表性任务和演示说明。
7. 保留开源许可、对应引擎源码和权重授权边界；不用于在线作弊。

本地测试不能代替公网安全与可靠性验收。此文为部署准备方案，不代表以上步骤已经执行。
