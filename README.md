# 棋理学伴

面向中国象棋初学者的短局面训练应用：先自行走棋，再用规则证据、分级提示和讲解理解这一步。

当前是 **v0.3.0 个性化教练版**。不需要注册，不依赖前端框架或运行时 npm 第三方包。Node.js 22.9+ 即可运行；开发测试另需 `npm ci` 安装 jsdom 和 pngjs（仅开发依赖）。应用支持本地运行；原型设计离线交付包见下方说明。

## 个性化教练与结构化棋盘（v0.3.0）

页面顶部的“我的专属教练”可选择年龄段、学习水平、练习目标和讲解节奏，默认适合 9–12 岁刚开始学棋的儿童。桌面展开设置，手机默认收起。教练按设置调整用语、术语解释、复盘重点和下一次练习；训练、导入残局、自由摆谱共用设置。档案只包含学习偏好，不要求姓名或学校。

训练页面可填写“这步想做什么”，AI 复盘会结合当前题最近最多 4 次尝试、是否借助提示、已有练习统计与自述计划，回应具体想法并留一个可独立完成的问题。近期尝试由服务端按题目和历史重新核验，明确区分非法、合法未达题目目标、提示后完成与独立完成；多步题另列红方走后与黑方自动应将后的局面。没有作答时说明是局面预习，不虚构学习者的错误。自由摆谱也可输入自己的计划。

棋盘统一建立红方固定坐标系：a0 为红方左下角，横向 a–i、纵向 0–9，数值坐标 x=0–8、y=0–9；翻转显示、黑方先行都不改变坐标。提供给模型的 `boardState` 包含 10×9 矩阵、红黑棋子清单、坐标定义、主线及分支的起终点、走前走后 FEN 和棋位变化。矩阵下标 `row=9-y`、`col=x`，空位为 `.`。训练棋盘下可展开坐标说明、查看选中棋子位置或导出结构化棋盘 JSON。

2026-11-03：180 项自动测试全部通过，无失败或跳过，20 题可解性检查通过，包含真实本地 Pikafish 检查；模型分支使用模拟接口。本版通过结构化上下文和教学提示实现个性化，没有对模型权重进行微调，也没有用真实付费模型验证儿童理解效果。新字段与验收方式见 `docs/PERSONAL-COACH.md`。

## 摆谱状态与回放核验同步（v0.2.10）

训练报告底部按实际回放 FEN 更新行棋方、合法走法数及局面判定，主线、分支及走前／走后保持对应。原始引用资料单独折叠保存，并注明“不随回放切换”。换题、重试或完成连续将杀的中间步骤时，清除上一局面的 AI 提示，不再保留“讲解已显示”或旧失败信息。

按使用者要求保留原提示词，着法引用、证据编号、候选着法或胜负措辞不一致时先显示模型原文，并附黄色一致性提醒，不再仅因此拦截整份讲解或要求付费补写。可阅读但略短的文字同样先显示。棋盘、参考着法与可回放线路继续来自本地工具，不采纳模型在正文中临时提出的着法。损坏 JSON、缺失步骤、重复编号或不可显示的字段结构仍返回错误。本轮 162 项测试全部通过，无失败或跳过，20 题可解性检查通过；没有追加真实模型调用。具体范围见 `docs/ADVISORY-COACH.md`。

## 逐步讲解与自由摆谱（v0.2）

普通题、预置残局、图片／FEN 导入残局共用逐步讲解器。每个红黑方步骤都包含目标、观察点、原因、走后结果和代表性变化；最后用一段整体总结串联思路。步骤选择器及前后按钮可定位棋盘，支持查看走前、走后和变化线路。

变化区分“其他正确解”“未达到限定目标”“其他合法防守”“合法参考”“尚未证实”和“非法尝试”。每步最多选取 3 个代表性变化，线路经规则重放核验；展示样本不等于穷举所有变化。规则搜索只判断限定步数内的连续将杀，不能把无短将杀说成实战必输，也不能把困毙算作将杀题的绝杀。

点击 **从此处开始摆谱**，可从主线或变化的当前局面自由走双方的棋，支持合法落点、键盘操作、悔棋、重摆和返回主线。摆谱不改变作答棋盘或训练记录。摆谱时隐藏原步骤讲解、导航、变化和总结，突出棋盘。走棋不自动调用模型，点击“AI 分析当前局面”后才发起请求，先看本步结论和建议，详细原因与应对在棋盘下方全宽展开。分析中仍可走棋，旧结果不会覆盖新棋盘。调用可能产生 API 费用。

先在 API 设置填写并应用当前页面的 DeepSeek Key。实时反馈先给出本步观察和下一步建议，详细解释与变化可展开。DS 使用服务端重建的当前局面和实际着法；引擎只给当前局面参考，未进行走前走后独立评分时，不声称本步损失了多少分。摆谱分支最多 80 步，单客户端每分钟最多 30 次分析请求。

本轮验证包括规则、真实 Windows 引擎、HTTP 接口和 jsdom 页面交互，模型输出使用 mock；未使用真实 Key 验证本版长讲解的生成效果。详细行为和验收记录见 `docs/DETAILED-COACH.md`。

讲解失败修复：提供每步完整合法候选，并区分有事实依据的“不能走”反例与实际可执行后续，避免坐标误拦；一次检查全部字段、精确补写有问题的分支，DS 少写分支时暂存结构化草稿，10 分钟内再次点击只补缺失或有误的部分。每次讲解请求仍只调用一次模型，补写后通过完整校验才显示；不需要刷新页面。

## 手动裁剪和棋位识别（v0.2.6）

v0.2.7 修复刷新后后台仍占用模型的问题：离开页面会中断对应请求并释放占用，后续阶段不会继续发起模型调用。残局、图片与四角、已完成的参考分析和 DS 讲解暂存在本标签页的 sessionStorage，刷新后恢复，不恢复忙碌标志、不自动重试；API Key 仍只在页面内存。存储不足时优先保留棋盘，页面提示是否需要导出。自由摆谱中的未保存分支不在此次暂存范围。详见 `docs/REFRESH-RECOVERY.md`。

选择图片后，按左上、右上、右下、左下选四个最外侧交叉点。边框与 9×10 网格实时显示；可拖动角点，或用百分比输入微调。原图方向由用户明确选择。没有自动定位调用，也没有逐格确认清单。

点击“裁剪识别＋字形复核”后，在浏览器内裁剪、透视校正，为 90 个固定棋位生成原色与黑白放大字形对照，先分两次请求交给 DS 转录文字与棋子，再独立复核最多 36 个已占用或可疑棋位，总计最多 3 次调用。棋位由程序绑定编号，DS 不能重新决定行列或旋转棋盘；本地颜色辅助校正红黑。冲突保留提示，可直接摆棋校正，无逐格确认。不会仅因缺少帅就凭位置补帅；须有复核字形支持。详见 `docs/MANUAL-VISION.md`。

v0.2.6 参考真人棋评的“目的—应对—具体结果—其他选择”组织统一内置提示词，研究出处与自编示范见 `docs/COACH-RESEARCH.md`。规则程序提供子力、炮架／马腿／象眼、合法吃子机会、帅将退路和具体攻击者；引擎补充同根局面、同深度的候选评分及可重放变化，不以规则合法性充当选着理由。每步分别展示其他走法和对手应对，避免只报合法走法数量。总结先给胜负结论：已证明时明确红胜或黑胜；缺少完整胜和负依据时标明胜负暂未确定，不把无短将杀、引擎零分或一条胜线当成和棋／必胜证明。当前未接入完整残局库及长将长捉和棋裁定。

“分析当前局面”在本地执行规则核验和引擎参考；“DS 逐步讲解”才调用模型。两者在页面明确标注。短杀范围收在高级设置，表示原行棋方最多走 1–3 次且每次都将军，不限制引擎或 DS 讲解长度。

## 启动

Windows 双击 `启动棋理学伴.cmd`，在浏览器打开 **http://127.0.0.1:8787/**。

新版源码包的内容、核验结果与分享边界见 `SUBMISSION.md`，伙伴操作清单见 `TESTING.md`。首次解压可运行 `node scripts/verify-package.js`，检查文件清单及 SHA-256。

也可以在此目录打开终端：

```powershell
node scripts/prepare-engine.js
node --env-file-if-exists=.env server.js
```

若权重缺失或损坏，可从固定上游提交补齐并校验：

```powershell
node scripts/prepare-engine.js --download
```

规则训练和教案不要求引擎就绪；点击“查看引擎参考分析”才启动 Pikafish。每次分析独立进程，单线程、64 MiB 哈希，搜索默认 600 ms，最多同时一个分析，避免持续占用 CPU。

按 Ctrl+C 停止终端服务。换端口时设置 `PORT`，见 `.env.example`。

## 模型功能与配置

点击页面右上角 **API 设置**，输入自己的 API Key，选择 `deepseek-flash`（默认）或 `deepseek-v4-pro`，点击“应用设置”后直接调用，无需重启。只支持页面手动输入，不再读取服务器环境中的模型密钥、模型名或接口地址。

“应用并测试连接”会向所选模型发送一次短请求，显示等待、成功、失败与原因。只应用设置不算测试成功。讲解和对照调用也会显示实际成功或失败，失败时不继续展示上一次的 AI 结果。

页面密钥只放在当前页面内存，经本机后端转发到 DeepSeek 官方接口，不写入浏览器存储或文件。清除按钮立即停用本页模型调用；刷新或重新打开页面后必须重新输入 Key，同一页面内连续调用无需重复填写。具体操作与验收见 `docs/API-PAGE-SETTINGS.md`。

本机已完成 DeepSeek API 基础联调，真实验证了车吃子和炮将杀两个代表局面，网页已能显示模型讲解。详见 `docs/API-VALIDATION.md`。其他电脑需要自行配置密钥；未配置时可查看本地参考着法和核验信息，详细讲解等待 DS 生成。

模型功能无需配置 `.env`。该文件只可选用于端口、监听地址、访问口令和引擎路径；即使旧文件留有 `LLM_API_KEY`、`LLM_MODEL` 或 `LLM_BASE_URL`，程序也不会使用它们。

分享项目压缩包时也要排除 `.env`；`.gitignore` 只影响 Git，不会自动过滤普通压缩包。

点击模型按钮后才会发起实际请求，可能产生费用。接口固定为 DeepSeek 官方 Chat Completions，不接受自定义接口地址；调用格式参考 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/)。

讲解使用 JSON 输出和启用思考模式（high），按步骤数分配最多 32000 tokens（包含模型推理与最终正文）的额度。图片识别及连接测试仍关闭思考。提示词仍要求完整步骤、变化和证据，并要求引用工具核验着法；v0.2.8 对讲解内容不一致采用提醒模式，保留原文显示，不把提醒变成付费补写条件。模型输出截断、结构缺失或字段无法显示时，各入口仍显示失败并保留局面和参考线路，不使用本地模板填充讲解区。单次讲解响应最多等待 120 秒，不会自动重试计费调用。

定制流程：按题目标签检索本地规则条目 → 生成实际着法的规则证据 → 可选调用棋力引擎 → 组织原教学提示 → 调用模型 → 检查可显示结构并生成内容一致性提醒 → 展示 DS 原文。本地模板仅作后台参考；页面保留参考着法和简短核验信息，等待、结构失败时不填入本地逐步讲解或总结。未调用 DS 时也可从选中的参考局面开始摆谱。

本版校验不等于自然语言解释的完整事实核验。已完成的 API 连通与代表局面检查，不替代大样本模型评测、教学可理解性或真实用户学习效果检查。

## 题目设计边界

吃子题考查明确的基础规则目标，不宣称该着法在实战中全局最优。应将题只要求解除当前将军。将杀题必须同时满足“对方正在被将军”和“对方无合法走法”，困毙虽然在象棋中是胜局，但不计为完成将杀题。

多步残局限定红方每步将军、两至三个红方回合内绝杀；规则搜索穷举黑方全部合法应对，接受所有满足此目标的着法。它不是通用残局库、完整自由对弈或长将长捉裁定系统，也不把引擎胜负评分直接当作本题通关条件。

预置内容适合局部规则与短战术练习，不提供完整比赛裁判功能，例如长将长捉和循环局面裁定。图片与 FEN 可导入自定义残局；暂不包含 XQF/CBR 二进制棋谱、整盘文字棋谱导入、完整对局复盘、在线双人对战和语音。图片识别必须人工核对，不能凭模型输出直接判胜。
